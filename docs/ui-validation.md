## 离线模式与外部数据模式

默认 E2E 使用真实 HTTP 服务、SQLite 账本和构建后的浏览器界面，但外部行情与新闻适配器明确返回“自动化测试未连接外部数据源”。没有模拟净值、伪造行情或随机构造盈利曲线。默认测试不依赖互联网，适用于 CI。

```sh
FINANCE_BROWSER_CHANNEL=chrome npm run test:e2e
```

设置 `FINANCE_LIVE_DATA=1` 后使用真实免费数据提供方。本次目视核验的总览曲线来自华安黄金 ETF 联接 A 的实际披露数据，来源及净值日期由页面显示；没有用付费模型生成曲线。

```sh
FINANCE_BROWSER_CHANNEL=chrome FINANCE_LIVE_DATA=1 npm run test:e2e
```

该模式依赖当时的网络与公开来源。测试接受“数据可得”或“明确报告缺失”两种合法状态，因此 **live 测试通过本身不证明所有基金数据均已成功取得**。基金目录数量、各产品历史点数和独立来源核对另见 [数据验收记录](data-validation.md)。

上面的命令选择已安装的 Chrome。使用 Playwright 管理的 Chromium 时可省略 `FINANCE_BROWSER_CHANNEL`，并按 Playwright 的安装提示准备浏览器；这不改变测试账户隔离方式。

## 账户与费用隔离

- 每轮测试使用新的 SQLite `:memory:` 数据库，连接地址为 `127.0.0.1:4321`。
- 测试显式提供 `keyProvider: () => undefined`，不读取用户 Keychain、环境密钥或个人数据库。
- OpenAI API 开关保持关闭，测试核对已计费金额为零；没有 Responses 或 Decisions 付费推理。
- 测试不操作银行或证券账户，也不发送手机消息。ChatGPT 通知显示待验收状态。
- 当前聊天、测试账本和合成账户名称不属于仓库种子数据；普通启动仍是空个人账本。

## 展示与失败状态复核

界面会将组合换算所需价格或有效汇率缺失显示为未知，不把缺失金额当作零。单只产品使用原币；组合汇总使用人民币；模型动作概率以百分数显示，综合评分为 0–10，二者不作为盈利概率。

历史曲线分别标注单位净值或日收盘价，并保留历史数据来源入口；基金/ETF 的净值序列不会因为最新快照来自场内报价就被改称成交价格。日收盘价也不表述为盘中逐笔行情。

本轮界面审查还补充了以下可见提示：本地快照读取失败时保留旧数据但明确标注读取中断；穿透覆盖、模型目录或申赎关联记录读取失败时说明原因；后台已启用但等待调度时显示“已启用”，不会误写成“已暂停”。购买渠道说明必须匹配账本账户名，候选金额、费用和净额使用一致币种，卖出比例明确为该产品总持仓口径。

组合穿透汇总仅针对真实持仓，按已确认标的合并，不猜测基金、FOF 或 ETF 未披露的下一层资产。权重分母为组合总资产；已解析和未解析金额仅统计投资部分，不把现金归为未解析资产。资料卡是本地生成的标题与来源预览，不声称是原站截图或已经阅读全文。
